# Starter Studio

把 ai-product-starter-kit 的分步开发方法变成一个本地中文工作台。整个项目沿一条流程推进：

**拖入 PRD → 模型提问 ↔ 用户回答 → 确认需求 → 生成技术文档 → 确认文档 → 保存代码书签 → 开发 → 人工验收 → 下一轮技术文档。**

页面只突出当前步骤，后续步骤按顺序解锁。支持同时管理多个软件，每个项目的需求、开发轮次、文档、书签与工作区相互独立。

- **搭建流程**：当前选中的软件。新建项目或点击「继续开发」会切换到它；刷新后会记住当前项目。
- **项目记录**：全部未归档项目。可以继续开发、查看记录或归档；只查看记录不会改变当前搭建的软件。
- **项目归档**：在侧栏最近项目下方收纳暂时停下的项目。记录仍可查看，点击「恢复到项目记录」后可从原步骤继续。

归档不会删除文件、文档、审批或书签，也不会自动推进步骤。任务运行中需先暂停或等待完成再归档。恢复项目不会启动模型。最近项目只展示未归档项目；新建入口保留在页面右上方，最近项目旁的加号已移除。当前页面与所选项目保存在网址中，刷新和浏览器返回可恢复；旧项目数据无需清空。

## 在线网站与源码

- 网站：https://owenmao-builder.github.io/starter-studio/
- 源码：https://github.com/owenmao-builder/starter-studio

GitHub Pages 运行的是**公开流程演示版**：使用同一套界面，可拖入 Markdown / TXT 体验逐步确认，数据只保存在当前浏览器。提问、方案和开发结果为标注清楚的固定示例；不会调用模型、生成代码或创建 Git commit。完整功能请按下方说明在本机运行。

`npm run build:pages` 将纯前端复制至被忽略的 `.pages-build/` 后静态导出到 `out/`，不包含服务端 API、`.studio` 数据或模型凭证。`main` 分支提交通过 GitHub Actions 自动发布到 Pages。本机版仍使用 `npm run dev` / `npm start`，两种构建相互独立。

## 启动

需要 Node.js 22.13+、npm、Git，以及已安装并登录的 Codex CLI：

```sh
npm install
npm run dev
```

打开 http://127.0.0.1:3100 。生产模式：

```sh
npm run build
npm start
```

同一时间只启动一个服务实例。数据保存在项目根目录的 `.studio/`；备份时保存整个目录。此工作台面向本机单用户，不能直接暴露到公网。

## 按顺序使用

1. 拖入 `.md`、`.txt`、`.docx` 或文字版 `.pdf`，最大 10 MB。导入后自动调用本机 Codex，以只读模式检查需求。可能消耗已配置账号的模型额度，上传区有明确提示。此时不会生成技术文档或代码书签。
2. 模型每轮最多提出 5 个必要问题，附选项、推荐和影响。可以「按推荐」，也可以写自己的答案或“不确定”。提交后继续检查，有关键缺口就再问一轮。
3. 模型整理需求确认单。用户确认目标、范围、费用和验收标准后，才生成第一轮技术文档；也可补充需求重新整理。
4. 审阅模型根据已确认需求和当前代码编写的技术文档。可以直接编辑或要求模型修改。变更后的文档需要重新确认。
5. 确认文档后，单独保存真实 Git 代码书签。该快照与本轮已确认文档绑定。
6. 书签保存成功后，允许本机 Codex 开发并点击开始。模型只获得当前轮次的开发范围。
7. 开发结束停在人工验收。未达预期可退回修改本轮方案；通过后可继续本阶段的下一个子轮次，或进入下一个生命周期阶段。
8. 验收通过后只生成下一轮文档，仍需确认文档、保存书签，再开始开发。

「项目记录」按需求问答和开发轮次收纳文档版本、确认记录、书签及活动。书签可下载 `.tar` 快照，解压到新目录查看或恢复，不覆盖当前代码。

项目代码：`.studio/workspaces/<项目 ID>/`；状态：`.studio/state/<项目 ID>.json`。项目 ID 见浏览器地址 `?project=...`。旧版项目保留已有文件、文档和书签，从需求澄清开始重新确认。

## 模型与顺序控制

优先检测 macOS ChatGPT 应用附带的 Codex，否则从 PATH 查找 `codex`。可用环境变量 `STUDIO_CODEX_BIN` 指定可执行文件。程序可用不代表已经登录；登录、网络或额度问题会停留当前步骤并提示重试。

需求分析和技术规划使用 `codex exec --json --sandbox read-only --output-schema ...`，返回值经结构校验。开发使用 `workspace-write` 沙箱，限定独立项目目录。不存在规则模板冒充模型生成的兜底。分析/规划超时为 5 分钟，开发超时为 20 分钟。

后端校验步骤、状态版本、需求哈希、文档版本与哈希、Git 内容和书签绑定。跳步、重复启动、过期页面或审批后改动代码会被拒绝。失败和重启不会自动执行后续步骤；开发中断后重新整理方案、确认、保存书签。

## 能力边界

- 已验证前后端顺序、文件解析、真实 Git 快照和状态持久化。真实模型生成质量与真实编码任务仍待验；交付联调使用隔离测试执行器，没有调用模型。
- 业务范围约束还依赖执行器遵守已确认技术文档；文件沙箱不是业务范围的形式化证明。
- 仅支持本机单用户、单服务实例。未实现公网鉴权、云同步、自动发布或扫描 PDF OCR。
- 强制关闭服务前请先在界面停止任务，避免失去外部进程跟踪。
- `.env`、私钥等常见敏感文件被 Git 忽略；凭证不要写入业务源码、PRD 或技术文档正文。
