# Starter Studio 顺序流程技术适配声明

## 目标与范围

把原工具包的阶段规则落实到界面和后端。导入 PRD 后只开始需求体检；模型提问与用户回答可循环。需求确认后生成具体技术文档，文档确认后保存 Git 书签，再授权本轮开发。每轮结束等待验收，通过后回到下一轮技术文档。

## 技术选择

使用 Next.js 16 App Router、React 19、TypeScript strict 和原生 CSS。保留本地 JSON 原子保存与 Git 快照，避免为单用户工作台引入数据库。前后端同源，只监听 loopback 地址。需要启动本机 CLI 并访问 Git 工作区，因此采用本地服务。

## 交互结构

左侧显示有连接关系的八步推进轨道；主区域只显示当前任务、上游输入和下一站。未来步骤锁定。项目记录按问答及开发轮次组织，文档和书签不再作为平行主入口。验收后可继续当前生命周期阶段的子轮次，或推进到下一阶段。

## 状态与数据

`questions ↔ 用户回答 → requirements → planning → document → bookmark → ready → development → review → planning（下一轮）`，最终可进入 `completed`。

Project 保存 revision、workflow、status、job、interview、requirementsHash/ConfirmedAt、round、stage、document/version/docHash、reviewTree、documents、approvals、bookmarks、lastRoundResult、result 与 activities。步骤与执行状态分离；失败不会推进步骤。

Approval 绑定 round、stage、version、docHash，文档确认时建立；后续书签保存成功再绑定 bookmarkId。Bookmark 保存真实 commit、轮次和阶段。下一轮规划携带上一轮验收结果及已有代码，避免丢失开发上下文。

## 接口

| 路径/操作 | 输入 | 结果与前置条件 |
| --- | --- | --- |
| GET /api/projects | 无 | projects 与 runner 状态 |
| POST /api/projects | multipart file | 解析 PRD，建立工作区，启动只读需求分析 |
| GET /api/projects/:id | 无 | 项目状态；重启后中断任务标为待恢复 |
| GET /api/projects/:id?bookmark=:id | 书签 ID | 真实 Git tar 快照 |
| analyze / answer / supplement | revision；answers 或 note | 当前问答或需求步骤，重新分析 |
| confirm_requirements | revision、requirementsHash、confirmed=true | 确认当前需求，进入规划 |
| plan / request_revision | revision；feedback | 只读生成或修改本轮技术文档 |
| revise | revision、document | 文档新版本，重新审阅，不保存书签 |
| confirm_document | revision、version、docHash、confirmed=true | 文档与代码内容一致，进入书签步骤 |
| bookmark | revision | 文档已确认且代码未变化，保存 commit |
| develop | revision、version、docHash、bookmarkId、confirmed=true | 书签与审批匹配、Git HEAD 一致且工作区干净 |
| accept | revision、verified=true、next=same/next | 仅限验收步骤，进入下一轮规划或完成 |
| cancel | revision | 停止运行中任务，保留当前步骤 |

项目操作统一为 POST /api/projects/:id JSON。错误返回 `{ error: { code, message } }`，常见状态 400/403/404/409/503。写操作核对 loopback Host、同源与 `x-studio-request: 1`。同项目操作使用进程内互斥锁，revision 防止过期提交。

## 执行器与边界

需求体检和规划使用 Codex read-only 沙箱与 JSON Schema，Zod 校验问题数量、字段及文档长度。每轮最多 5 个必要问题。规划发现必要缺口时回到问答，重新确认需求。

开发使用 workspace-write 沙箱。Prompt 明确限定本轮已确认文档，禁止开始下一轮、对外发消息、创建付费资源、正式发布或修改工作台状态。开发结束等待人工验收。无模板生成兜底。超时、无 CLI、无登录、模型格式错误、进程失败会在当前步骤显示错误，不自动重试。

## 验证与恢复

14 项测试覆盖核心步骤和真实 Git。隔离执行器验证接口和浏览器从上传到第二轮文档的完整流转；真实模型质量仍待验。既有项目保留源文件、历史文档及书签，从需求澄清重新进入流程。快照导出后可在新目录恢复，不直接重置当前代码。
